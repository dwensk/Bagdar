# Bagdar

## Подтверждение почты и восстановление пароля

В текущей версии аккаунты остаются в существующей базе Neon/PostgreSQL.
Supabase Auth для этих аккаунтов не используется. Настройки SMTP, сохранённые
в панели Supabase, автоматически не передаются серверу Vercel.

До публикации новой версии добавьте в Vercel → Project → Settings → Environment Variables:

| Переменная | Значение |
| --- | --- |
| `SMTP_HOST` | `smtp.gmail.com` или SMTP вашего провайдера |
| `SMTP_PORT` | `465` для TLS или `587` для STARTTLS |
| `SMTP_USER` | Почта отправителя |
| `SMTP_FROM` | Та же почта либо подтверждённый адрес отправителя |
| `SMTP_PASSWORD` | Отдельный пароль приложения Google / SMTP-пароль |
| `EMAIL_CODE_SECRET` | Независимый случайный секрет длиной не менее 32 символов |

Оставьте существующие `DATABASE_URL` и `ADMIN_EMAILS` без изменений.
Эти переменные нужны только серверу. Их нельзя записывать в `assets/js`,
коммитить или показывать на странице. Пример без секретов — `.env.example`.
Для запуска требуется Node.js 20 или новее.

Регистрация отправляет шестизначный код. Аккаунт и сеанс создаются после
подтверждения. Код действует 10 минут и допускает максимум 5 попыток ввода.
Повторная отправка доступна раз в минуту, максимум 6 писем на адрес в час.
Есть отдельный лимит по IP, общий для экземпляров сервера Vercel.

«Забыли пароль?» отправляет код на существующую незаблокированную почту.
После проверки сервер выдаёт отдельный одноразовый билет для смены пароля.
Его срок — 10 минут; в базе хранится только хеш. После успешной смены
старые сеансы входа закрываются. Для отсутствующей почты интерфейс показывает
то же сообщение, но аккаунт не создаётся и письмо не отправляется.

Миграция добавляет поля `email_verified_at`, `last_login_at` и служебные таблицы
при первом запросе API. Старые аккаунты, оплаты, история и чек-листы сохраняются.
Старые адреса не считаются подтверждёнными автоматически: в аккаунте есть
кнопка подтверждения. Пользователи продолжают входить со своими паролями.

CSV в админ-панели включает UUID, имя, email, роль, статус подтверждения,
даты подтверждения и входа, подписку, блокировку и дату регистрации.
SQL для просмотра этих данных без паролей — `sql/users-directory.sql`.
Выполняйте его в существующей базе Neon. Роль администратора определяется
серверным списком `ADMIN_EMAILS`; поле `stored_role` в SQL носит справочный характер.

Проверки: `npm ci`, затем `npm test`. Автотесты используют изолированную
PostgreSQL-совместимую базу pg-mem и подменяют отправку почты. Они не отправляют
реальные письма и не доказывают доставку Gmail.
После настройки переменных и деплоя обязательно проверьте настоящую регистрацию,
получение письма, неверный код, восстановление и вход с новым паролем.
`/api/health` показывает `emailVerification` и `mailConfigured`, без значений секретов.

## Архитектура

```
Браузер (index.html + assets/js)  ──fetch──▶  API на Vercel (папка api/)  ──SQL──▶  PostgreSQL (Neon)
```

- **Фронт** — статический сайт: HTML, CSS, JavaScript без фреймворков.
- **Бэкенд** — серверные функции Node.js на Vercel, папка `api/`.
- **База данных** — PostgreSQL в Neon. Таблицы создаются автоматически при первом запросе (`lib/db.js`).

### API

| Метод и адрес | Что делает |
|---|---|
| `POST /api/auth?action=register` | Регистрация (всегда обычный пользователь) |
| `POST /api/auth?action=login` | Вход, выдаёт токен |
| `POST /api/auth?action=logout` | Выход, токен удаляется из базы |
| `GET /api/me` | Профиль, оплаты, история расчётов, чек-листы |
| `POST /api/pay` | Оформить подписку Pro (демо-оплата) |
| `POST /api/history`, `DELETE /api/history?id=` | Сохранить или удалить расчёт |
| `POST /api/checks` | Отметить документ в чек-листе |
| `GET /api/admin`, `POST /api/admin` | Админ: пользователи, оплаты, статистика; выдать или отозвать подписку, блок, удаление |
| `GET /api/programs?pair=&score=&sort=&grant=1` | Специальности по паре предметов ЕНТ: фильтр по баллу и сортировка на сервере |
| `GET /api/uniprices?uni=` | Стоимость по программам бакалавриата в вузе, по направлениям |
| `GET /api/health` | Проверка, что сервер и база работают |

### Таблицы

`users`, `sessions`, `payments`, `history`, `checks`, `programs`, `uni_prices` (см. `lib/db.js`).

### Источники данных

- Специальности, пороги на грант, зарплаты и трудоустройство: [joo.kz](https://joo.kz/professions/), 105 специальностей по 12 парам предметов, собрано 13.10.2026 (`lib/programs.js`).
- Цены вузов: BAQ.KZ, 11.08.2026 и [Univision.kz](https://univision.kz/univ/price.html) — у 67 вузов сводная цена, у 58 — цены по каждой программе бакалавриата (2 344 программы, `lib/uniprices.js`).

### Безопасность

- Пароли хранятся как хеш scrypt с солью, сам пароль в базе не хранится.
- В базе хранится не токен входа, а его SHA-256.
- Все проверки (e-mail, пароль, код админа, права админа, сумма оплаты) делает сервер.
- SQL-запросы параметризованы, поэтому SQL-инъекции невозможны.
- Админ-права есть только у аккаунтов из переменной `ADMIN_EMAILS` на сервере: зарегистрироваться админом с сайта нельзя.

## Деплой

1. Vercel → **Add New → Project** → импортировать этот репозиторий → **Deploy**.
2. В проекте Vercel: **Storage → Create Database → Neon (Postgres)** → подключить к проекту. Vercel сам добавит переменную `DATABASE_URL`.
3. **Settings → Environment Variables**: добавить `ADMIN_EMAILS` — e-mail администратора (несколько — через запятую).
4. **Deployments → Redeploy**.

Оплата работает в демо-режиме: подписка оформляется на сервере, но деньги не списываются. Для настоящих платежей нужно подключить Kaspi Pay или эквайринг банка.
